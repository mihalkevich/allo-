# 18. ТЗ: агент-сборщик контактов

Агент автоматически заполняет контактные поля в `companies-base.csv`,
собирая публичные данные с официальных сайтов компаний.

> Заодно это демо собственного продукта «Нейросети» — на мероприятии можно
> показать агента в работе.

## Задача

Вход: `companies-base.csv` (215 компаний, поля контактов пустые).
Выход: тот же CSV с заполненными `Сайт`, `Телефон`, `Email`, `Соцсети`
и, где доступно публично, ФИО/должность профильного руководителя.

## Что собирает

| Поле | Источник | Правило |
|------|----------|---------|
| Сайт | Поиск по названию | Официальный домен компании |
| Телефон | Страница «Контакты» | Формат +375 XX XXX-XX-XX |
| Email | «Контакты», футер | Корпоративный (info@, office@, pr@) |
| Соцсети | Футер, шапка сайта | Ссылки на офиц. аккаунты |
| ЛПР (опц.) | «Руководство», «О компании» | Только публично указанные ФИО/должность |

## Алгоритм по каждой строке

1. Если `Сайт` пуст — найти официальный сайт по названию компании.
2. Открыть сайт, проверить `robots.txt` — уважать запреты.
3. Найти страницу «Контакты» / «О компании» / «Руководство».
4. Извлечь телефон, email, ссылки на соцсети.
5. Нормализовать: телефон в `+375…`, email в нижний регистр, валидировать.
6. Записать в CSV; проставить `Статус`:
   - `собран` — найдены телефон и email;
   - `частично` — найдено не всё;
   - `не найден` — данных нет, нужен ручной разбор.
7. В колонку `Источник` (добавить) — URL страницы, откуда взяты данные.

## Правила легальности (обязательно)

- Только **публичные контакты уровня организации** с официальных сайтов.
- Уважать `robots.txt` и условия использования сайтов.
- **Не** собирать персональные данные физлиц из закрытых разделов, соцсетей
  за авторизацией, баз за паролем.
- **Не** обходить капчи и блокировки.
- Rate-limiting: пауза между запросами к одному домену, реалистичный
  User-Agent, не более N запросов/мин.
- Результат — контакты для **делового приглашения организаций**, не «база для
  рекламных рассылок физлицам» (см. `12`).

## Валидация и качество

- Email — проверка по regex и на доменное соответствие сайту.
- Телефон — проверка кода страны/оператора Беларуси.
- Дубликаты доменов — отметить.
- Низкая уверенность — `Статус = частично`, на ручную проверку OUT.
- Контрольная выборка: OUT вручную проверяет 10–15% строк.

## Технические варианты реализации

- На платформе «Нейросети» — собственный агент с веб-доступом (приоритет:
  это и продукт, и демо).
- Готовый no-code/RPA-сценарий с веб-скрейпингом.
- Скрипт (Python: requests + парсер HTML) с очередью доменов.

Во всех вариантах — соблюдать раздел «Правила легальности».

## Формат вывода

`companies-base.csv` с добавленной колонкой `Источник`:

```
Компания,Отрасль,Сайт,Целевая роль,Канал,Телефон,Email,Соцсети,Приоритет,Статус,Источник
```

## Очередь обработки

1. Приоритет A (банки, АЗС, HoReCa, телеком, ритейл) — первыми.
2. Приоритет B — далее.
3. `Статус = не найден / частично` — список на ручной добор силами OUT.

## Definition of Done

- [ ] ≥ 90% строк приоритета A со статусом `собран`.
- [ ] ≥ 70% всех строк со статусом `собран` или `частично`.
- [ ] Контрольная выборка проверена вручную, ошибок < 5%.
- [ ] Файл передан OUT для запуска outreach (`17`).
